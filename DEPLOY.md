# Публикация прототипа на Railway

Прототип — это фронт (Vite) плюс мини-сервер (Express), который хранит правки,
комментарии и директивы в файлах. Боевой адрес:
<https://inclusion-editor-production.up.railway.app>

> **Пароля нет — доступ открыт по ссылке.** Любой, кто знает адрес, может читать,
> менять и удалять правки и комментарии; удаление необратимо. Обоснование — в
> комментарии `server/index.js` над роутером. Страховка — бэкапы (см. ниже).

---

## Как публиковать

Railway берёт код из GitHub, из ветки **`release`**. Публикация — это одна
команда из папки `prototype/`:

```bash
git push origin main main:release
```

Она отправляет наверх текущую `main` и переводит на неё `release`. Railway видит
изменение ветки `release`, забирает код у себя и собирает образ по `Dockerfile`.
Всё вместе занимает около минуты.

**Обычный `git push origin main` сайт не меняет.** Код уезжает в репозиторий,
но публикация не запускается — она привязана только к `release`. Так сохранение
версий и выкладка разведены: незаконченная работа соседней сессии на боевой
стенд сама не попадёт.

### Почему не `railway up`

Ручная заливка (`railway up`) продолжает работать и годится как запасной путь,
но у неё два минуса. Она каждый раз пакует и заливает всю папку — это 19 МБ
против нескольких килобайт при пуше. И она публикует то, что лежит на диске,
включая чужие несохранённые правки, а сборка из `release` берёт ровно то, что
закоммичено.

### Проверить, что вышло

```bash
railway status
```

Смотреть на статус последнего деплоя и на хэш коммита. Содержимое проверять по
самой странице, а не по имени файла сборки: Railway собирает у себя, и имя
отличается от локальной сборки при том же коде.

## Настройки на Railway (уже сделаны)

| Что | Значение | Зачем |
|---|---|---|
| Source | `sailorstale/inclusive-employment-prototype`, ветка `release` | откуда берётся код |
| `DATA_DIR` | `/data` | папка тома с правками и комментариями |
| Volume | смонтирован в `/data` | без него данные сотрутся при передеплое |
| `PORT` | *(не задавать)* | Railway проставляет сам |
| Healthcheck | `/api/auth` | Railway ждёт ответа отсюда, иначе деплой не встаёт |

Сборка описана в `Dockerfile` (два этапа: сборка фронта отдельно, в готовый
образ едут только `dist`, `server` и рабочие зависимости) и в `railway.json`.

## Свой домен

**Settings → Networking → Custom Domain** → ввести домен. Railway покажет
`CNAME`, который надо прописать у регистратора.

## Данные и бэкапы

Данные прода и локальные не связаны. Правки на сервере лежат в своём томе, а
локально — в `prototype/data/`. Разметка, сделанная на своей машине, на боевом
стенде сама не появится.

Бэкап боевых данных — кнопка «Скачать бэкап» на странице `/changes` (выгрузка
всех правок и комментариев в JSON). Локальная папка `data/` копируется
ежедневно автоматически.

> Примечание: GitHub Pages-деплой (`.github/workflows/deploy.yml`) — отдельная
> витрина без сервера; там правки в общий стор не сохраняются. Боевой общий
> редактор — это Railway-версия.
